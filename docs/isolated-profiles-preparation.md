# 계정별 독립 실행 — 실험 기능

현재 상태: **v0.3.0에서 메뉴에 연결했습니다. 별도 로그인과 사용자 데이터 폴더로 독립 인스턴스를 여는 실험 기능입니다. 실제 두 계정의 동시 로그인과 장시간 사용은 아직 검증하지 않았습니다.**

## 확인한 근거

설치된 ChatGPT/Codex 앱 버전 `26.915.31945`의 번들 코드를 읽기 전용으로 확인했습니다.

- `bootstrap-DF0QwAxC.js`: `CODEX_ELECTRON_USER_DATA_PATH`를 읽어 Electron의 `userData` 경로를 설정합니다. 명시적인 사용자 데이터 경로 여부가 단일 인스턴스 처리에 전달됩니다.
- `main-DUHZj4_w.js`: 별도 Codex 홈과 별도 Electron 사용자 데이터 경로를 함께 지정하고 `open -n`으로 데모 앱을 여는 코드가 존재합니다. 셸 환경을 다시 읽을 때에도 명시적으로 지정된 Codex 홈을 유지하는 코드가 있습니다.
- [OpenAI 공개 환경 변수 문서](https://learn.chatgpt.com/docs/config-file/environment-variables)는 `CODEX_HOME`이 인증·설정·세션 등의 루트이며, 별도로 지정하는 `CODEX_SQLITE_HOME`도 있음을 설명합니다.

이 근거로 계정별 독립 인스턴스를 준비할 수 있습니다. 다만 Electron 경로 옵션은 공개된 안정성 계약이 아니며, 위 데모 코드의 존재가 모든 로그인·딥링크·업데이트 동작의 격리를 보장하지는 않습니다. 실제 두 계정 동시 실행은 미검증입니다.

## 준비된 구현

`Sources/IsolatedProfiles.swift`의 `IsolatedLaunchPlan`은 퍼스널·비즈니스 슬롯마다 다음 경로를 계산합니다.

```text
~/Library/Application Support/Codex Account Switcher/isolated-profiles/
  personal/
    codex/       인증·설정·작업 기록
    desktop/     창 상태·브라우저/앱 사용자 데이터
  business/
    codex/
    desktop/
```

`open`에 넘길 인자 배열에는 슬롯별 Codex 홈, Electron 사용자 데이터 경로, `--user-data-dir`가 포함됩니다. 쉘 문자열로 조합하지 않으므로 앱 이름과 경로의 공백을 유지합니다. 현재 프로세스에서 상속한 인증 토큰, 다른 앱의 RPC 파이프, 별도 SQLite 경로 등은 향후 런처에서 전달하지 않도록 환경 필터를 준비했습니다.

`prepareFreshDirectories()`는 호출 시 빈 디렉터리와 파일 기반 인증 설정만 생성합니다. 기존 프로필은 수정하지 않고, 경로의 심볼릭 링크를 거절합니다. 사용자가 메뉴에서 새 슬롯을 처음 열 때만 호출합니다. 다시 열 때는 기존 프로필 구조와 권한을 검사하고 내용을 유지합니다.

**계정 토큰은 현재 로그인이나 키체인에서 복사하지 않습니다.** 각 슬롯에서 별도 로그인으로 새 세션을 발급받는 방식으로 준비했습니다. 두 실행이 같은 갱신 토큰을 공유하는 문제를 피하기 위해서입니다. 슬롯 이름은 로그인된 계정을 보장하지 않으므로 실제 로그인 후 계정·워크스페이스 확인이 추가로 필요합니다.

기존 프로젝트·대화 기록은 자동 복제하거나 공유하지 않습니다. 독립 실행 창의 초기 목록은 비어 있을 수 있으며, 기존 앱의 기록은 원래 위치에 남습니다. 이미 열린 대화를 다른 계정으로 옮기는 기능은 이 준비에 포함하지 않습니다.

## 실행 없이 확인

```sh
./scripts/test.sh
build/CodexAccountSwitcher-tests --plan-isolated-profile personal
build/CodexAccountSwitcher-tests --plan-isolated-profile business
```

두 `--plan-isolated-profile` 명령은 JSON 실행 계획만 출력합니다. 실제 프로필 폴더를 만들거나 앱을 실행하지 않습니다. 메뉴의 ‘계정별 독립 실행 (실험)’을 선택하면 별도 앱을 실행합니다.

검사는 임시 폴더의 합성 데이터로 경로 분리, 읽기 전용 실행 계획, 환경 변수 제한, 파일 권한, 기존 폴더 보호, 심볼릭 링크 거부를 확인합니다.

## 검증 범위와 남은 작업

1. **검증 완료:** 로그인하지 않은 독립 실행 2개가 서로 다른 PID로 유지되고 각 사용자 데이터 폴더가 생성되는 것을 확인했습니다. 원래 프로세스와 로그인 파일은 유지됐습니다. 테스트 프로세스만 종료했습니다. SQLite 경로와 실제 인증 갱신은 추가 검증 대상입니다.
2. 각 슬롯에서 새 브라우저 로그인을 진행하고, 퍼스널·비즈니스 계정과 워크스페이스가 올바른지 검증합니다. 콜백 포트 충돌을 피하도록 로그인은 순서대로 진행합니다.
3. 독립 실행별 PID와 시작 시각, 프로필 경로를 추적합니다. 앱 재시작 이후에도 인스턴스를 재식별해야 합니다.
4. **구현 완료:** 독립 인스턴스, 여러 인스턴스 또는 식별하지 못한 프로세스가 있으면 일반 전환을 차단합니다. 종료 대기 중 다른 Codex가 시작돼도 로그인 파일을 교체하지 않습니다. 독립 실행 메뉴 자체는 프로세스를 종료하지 않습니다.
5. 선택한 인스턴스만 종료·재실행하고 다른 인스턴스의 작업이 유지되는지 확인합니다. 기존 창의 대화를 유지하면서 계정만 바꾸는 기능과는 구분합니다.
6. 딥링크와 OAuth 콜백, 앱 자체 업데이트, 원격 연결·플러그인·키체인 등 전역 서비스가 다른 계정 창에 잘못 연결되지 않는지 확인합니다.

실제 계정 로그인과 장시간 동시 사용 검증이 남아 있으므로 메뉴와 릴리스에 실험 기능임을 표시합니다. 기본 로그인 방식은 유지하고 독립 실행은 사용자가 메뉴에서 선택했을 때만 시작합니다.

선택적 통합 검사: `./scripts/smoke-isolated.sh`. 설치된 Codex와 기존 파일 기반 로그인이 필요합니다. 임시로 로그아웃 상태인 앱 두 개를 열어 검증하고, 그 두 프로세스만 종료합니다. 일반 CI에서는 실행하지 않습니다.
